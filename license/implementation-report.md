# Implementation Report: 247

## Plan Deviations & Rationale

No scope deviations. All six files specified in the plan were created in `/task-247/`; the website repository is untouched. The following are drafting refinements made *within* the plan (its own testing strategy, manual-verification step 6, requires fixing drafting that a fresh-eyes reviewer finds uncertain), plus two minor additions:

1. **Fresh-eyes review fixes (LICENSE.md).** Two independent non-drafter reviewers (LLMs, per the plan's fresh-eyes test) answered all four comprehension questions correctly, but reviewer 1 flagged ambiguity. Fixed, then confirmed resolved by reviewer 2:
   - §1 "Threshold": the phrase "exceeds the Threshold" is now an explicitly defined term including "equal to or greater than", with an express "exactly at either figure" clarification (ordinary usage of "exceeds" implies strictly greater).
   - §5 grace period: now states use *during* the grace period is a Permitted Free Use, and that an Organization is entitled to one grace period only (no second grace on re-crossing). §9 breach wording changed from "including after expiry" to "after expiry … (or where no grace period applies)" so during-grace use cannot be read as a breach.
   - §1/§5 aggregation: "all Affiliates under common Control" → "all of its Affiliates" ("Affiliates" already covers parents/subsidiaries/siblings; the old phrasing could be read as narrowing the perimeter).
2. **Fresh-eyes review fixes (round 2, LICENSE.md §2/§4/§6).** Patent grant aligned with the copyright grant to include internal **Modify** (previously "make and use" only — a coverage gap); §4(b) reworded to "either does not exceed the Threshold or is within the grace period" (the old parenthetical conflated the two concepts); §6(b) prefixed with "without limiting paragraph (a)" to signal the enumeration is intentionally belt-and-suspenders (the plan's acceptance criterion requires both limbs). The same §6(b) prefix was applied in COMMERCIAL-LICENSE.md to keep §6 mirroring exact, as the plan requires.
3. **Minor addition — audit frequency cap (COMMERCIAL-LICENSE.md §7).** "No more than once per year" limits both the certification request and the audit right. Not specified in the plan; standard audit-clause practice, fixed (not a placeholder), protects the Customer and is expected in such clauses. Impact: none on plan requirements. (The entire audit clause, including this cap, was subsequently removed at user direction — see item 7.)
4. **Minor addition — USD 100 liability cap (LICENSE.md §11).** The plan required a Limitation of Liability section but did not specify a cap. A nominal cap was added (standard in source-available/proprietary licenses) so the exclusion is not left entirely to "maximum extent permitted by law", which can fail in some jurisdictions. Impact: none on acceptance criteria.
5. **IP Indemnity removed from COMMERCIAL-LICENSE.md (user-directed, post-implementation).** Plan acceptance criterion 7 required an IP indemnity section; the user directed its removal after reviewing the risk analysis. Rationale: pre-incorporation the licensor is a natural person, so an indemnity would be backed by personal assets with no entity and no tech E&O insurance behind it — an unfundable promise that creates false expectations. With §9 already disclaiming any warranty of non-infringement, third-party IP-claim risk now sits with the Customer. Impact: §§12–14 renumbered to 11–13, the termination survival list updated, and a note added to the solicitor-review checklist item. An indemnity can still be offered deal-by-deal via an Order Form once the licensor is incorporated/insured, since §12 provides that the Order Form prevails over the Agreement in case of conflict — no skeleton amendment needed.
6. **Kept as drafted despite reviewer suggestions (plan-mandated text).** The $10,000 single-month Total Expenditure test (reviewer 2 noted it is aggressive — most functioning organizations exceed it) and the "substantially similar functionality" breadth of "Competing Product" are the plan's exact, user-agreed drafting and were not altered. Flagged for the solicitor review via Known Limitations below.
7. **Verification and Audit clause removed from COMMERCIAL-LICENSE.md (user-directed, post-implementation).** Plan acceptance criterion 7 required an audit/verification clause; the user directed its complete removal ("adds friction with no benefit") after being shown a slimmed certification-only alternative. Consequence recorded: the clause was the only compliance-verification mechanism in the document set — the Threshold and the Authorized Scope are now enforced purely by self-reporting (honor system), with no records duty, certification, or audit right; under-reporting is undiscoverable until technical enforcement (license keys) exists. Impact: §§8–13 renumbered to 7–12, the termination survival list updated, the four audit placeholders (`[3]`, `[30]`, `[5]`, `[4]`) and the audit checklist item removed from PRE-LAUNCH-CHECKLIST.md, and the solicitor-review item extended to flag the absence of any verification mechanism.
8. **Support and maintenance excluded; public-updates-only (COMMERCIAL-LICENSE.md §7, user-directed).** The plan's structure made support/updates available "only as stated in the Order Form" (i.e., sellable support). Per user direction, §7 now states that no support or maintenance is provided and no service levels apply; Customer receives only the same updates as are released publicly, "AS IS" (cross-referencing the §8 disclaimer), and is solely responsible for obtaining, applying, and verifying updates. Per-deal support can still be added via an Order Form, which prevails over the Agreement (§12) — no skeleton amendment needed. Impact: the standard commercial offering is license-only.
9. **Minor addition — no-roadmap-influence clause (COMMERCIAL-LICENSE.md §7).** Not in the plan; added per user query to pre-empt the common paying-customer assumption that fees buy roadmap influence, priority pull-request review, or feature-request commitments. Drafted with lowercase "contributions" (the defined term "Contribution" lives in the CAA and is not incorporated into the Commercial Agreement's definitions) and as "nothing in this Agreement", so an Order Form can still grant such commitments per-deal (Order Form prevails, §12). Impact: none on acceptance criteria.
10. **Liability-cap carve-outs added (COMMERCIAL-LICENSE.md §9, post-review, user-directed).** Review found the mutual aggregate cap would also cap the Customer's liability to Licensor — defusing the core enforcement scenario (a customer reselling the Software could limit exposure to 12 months of fees). Added a carve-out sentence: the cap does not apply to Customer's obligation to pay Fees due, Customer's liability for breach of Section 6 (Restrictions), or either party's liability for breach of Section 11 (Confidentiality). The cap's lead-in was changed from "Subject to the following sentence" to "Subject to the remainder of this Section" accordingly. A companion fix remains offered but not applied: scoping the §12 Order-Form-prevails clause so an Order Form cannot vary Section 6 or Section 9 unless it expressly says so.
11. **License-back kept unrestricted (CONTRIBUTOR-ASSIGNMENT-AGREEMENT.md §6, user-directed after extended review).** Discussion identified that the unrestricted license-back ("for any purpose") lets even a very prolific contributor aggregate their assigned contributions and reuse them in a competing product. A "no Competing Product" carve-out was drafted, applied, and then **removed at user direction** as inconsistent with the win-win contributor posture: the license-back is the contributor's one tangible give-back in a full-assignment CAA, and the carve-out's unique protection covered only the lazy-copy path (genuine rewrites are always lawful; SlopOn itself and all code written by others remain fully protected regardless, since the license-back covers only the contributor's own Contributions). Final position: full "for any purpose" license-back, as originally drafted. Enforceability analysis recorded for the solicitor: reuse of assigned code beyond the license-back's scope is copyright infringement with injunction/account-of-profits remedies, and "rebuilt from knowledge" is an evidence-dependent defense (subconscious copying still infringes; access is undeniable for contributors).

## Known Limitations & Follow-ups

- **Not legal advice; mandatory solicitor review pending.** Custom text modeled on the BSL 1.1 structure. Independent England & Wales solicitor review is checklist item 7 and is a launch gate. Specific items flagged for that review: enforceability of the total distribution ban in EU jurisdictions with strong exhaustion doctrines (plan risk), CAA assignment/fallback mechanics in assignment-hostile jurisdictions (e.g. Germany), and the breadth of the "Competing Product" definition ("substantially similar functionality").
- **Substantive threshold harshness.** The USD 10,000 single-month Total Expenditure test will exceed for most functioning organizations (any employer with a single month of payroll likely crosses it). This is the user-agreed drafting ("exactly as agreed" per plan) and is presented transparently in LICENSING.md, but expect positioning/FAQ questions at launch (plan already records this risk).
- **Threshold self-measurement.** Gross Revenue/Total Expenditure definitions are deliberately broad; measurement cadence, exchange-rate source, and treatment of pass-through funds/grants/loans are unspecified ("prevailing exchange rates"). Candidates for solicitor refinement or an FAQ; left simple per plan.
- **Output clause disclaims ownership, does not guarantee user ownership.** Reviewer 1 noted §3 does not positively guarantee the user owns Output (third-party rights in inputs, training-data questions). Standard for tool licenses; noted for transparency.
- **No IP indemnity in the commercial agreement.** Customers bear third-party IP-claim risk on their own use; expect procurement friction with larger organizations. Revisit — globally or per Order Form — once the licensor is incorporated and can obtain tech E&O insurance. Flagged for solicitor review via PRE-LAUNCH-CHECKLIST.md item 6.
- **Enforcement is now purely honor-system.** No license keys/telemetry (out of scope per plan), and the audit/verification clause — previously the only compliance-verification mechanism — was removed at user direction. Threshold and Authorized Scope compliance are self-reported and unverifiable; technical enforcement (license keys) is the follow-up engineering task that can restore verification. Flagged for solicitor review via PRE-LAUNCH-CHECKLIST.md item 6.
- **Open pre-launch items** (all tracked in PRE-LAUNCH-CHECKLIST.md): licensor legal name, commercial contact email, order-form/pricing URL, liability-cap figure, scope model + pricing decision, solicitor review, commit to product repo, source-file license headers (`SPDX-License-Identifier: LicenseRef-SlopOn-Community-1.0` suggested), CAA signing bot, website `/license` page, trademark registration.
- **Files not yet committed.** The task repo has no commits yet (baseline state); deliverables are untracked files ready for review before committing to the product repository per checklist item 8.
